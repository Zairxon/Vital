# Vital — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Android-приложение Vital, где документы семьи лежат в телефоне, ищутся по человеку и типу, открываются с зумом и отправляются через «Поделиться».

**Architecture:** React + Vite собирается в статику и упаковывается Capacitor в APK. Байты файлов и JSON с описаниями лежат в приватной папке приложения; в браузере те же интерфейсы работают через IndexedDB и localStorage, поэтому весь интерфейс разрабатывается и проверяется без телефона. Чистая логика (модель, поиск, PIN) вынесена в `src/lib/` и покрыта юнит-тестами.

**Tech Stack:** React 19, Vite, Capacitor 7 (`@capacitor/camera`, `@capacitor/filesystem`, `@capacitor/share`, `@capacitor/preferences`, `@capacitor/app`, `@capawesome/capacitor-file-picker`, `@aparajita/capacitor-biometric-auth`), react-router-dom (HashRouter), react-zoom-pan-pinch, fflate (ZIP), vitest.

**Spec:** `docs/superpowers/specs/2026-09-22-vital-design.md`

## Global Constraints

- Приложение работает **полностью офлайн**: ни одного сетевого запроса, никакой аналитики.
- Файлы документов — только в приватной директории приложения (`Directory.Data`, подпапка `vital/`). Никогда не в публичные `Documents`/`External`.
- Язык интерфейса — русский. Коммиты — по-русски, в конце строка `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Тема «Botanical Earth», токены копируются один в один из `C:\Projects\buildflow\src\styles\variables.css`, шрифт Inter. Тёмная тема — основная.
- Android: `appId` = `com.zairxon.vital`, `appName` = `Vital`, minSdk 23.
- Ни один слой интерфейса не вызывает Capacitor напрямую — только через `src/lib/`.
- После каждой задачи: `npm run build`, затем коммит.

```js
// src/lib/__tests__/model.test.js
import { describe, it, expect } from 'vitest';
import {
  emptyDb, addPerson, updatePerson, removePerson, movePerson,
  addDocument, removeDocument, togglePin,
} from '../model.js';

const page = (fileId) => ({ fileId, kind: 'image', mime: 'image/jpeg', size: 100, name: 'p.jpg', thumbId: fileId + '_t' });

describe('люди', () => {
  it('добавляет человека с id и порядком', () => {
    const db = addPerson(emptyDb(), { name: 'Отец', relation: 'отец' });
    expect(db.people).toHaveLength(1);
    expect(db.people[0].name).toBe('Отец');
    expect(db.people[0].order).toBe(0);
    expect(db.people[0].id).toBeTruthy();
  });

  it('не меняет исходную базу', () => {
    const before = emptyDb();
    addPerson(before, { name: 'Мать' });
    expect(before.people).toHaveLength(0);
  });

  it('удаляет человека вместе с его документами и возвращает файлы на удаление', () => {
    let db = addPerson(emptyDb(), { name: 'Сын' });
    const pid = db.people[0].id;
    db = addDocument(db, { personId: pid, type: 'passport', title: 'Паспорт', pages: [page('f1')] });
    const res = removePerson(db, pid);
    expect(res.db.people).toHaveLength(0);
    expect(res.db.documents).toHaveLength(0);
    expect(res.orphanFileIds).toEqual(['f1', 'f1_t']);
  });

  it('меняет порядок людей', () => {
    let db = addPerson(emptyDb(), { name: 'A' });
    db = addPerson(db, { name: 'B' });
    const bId = db.people[1].id;
    db = movePerson(db, bId, -1);
    expect(db.people.map(p => p.name)).toEqual(['B', 'A']);
  });

  it('не ломает порядок на границах списка', () => {
    let db = addPerson(emptyDb(), { name: 'A' });
    db = movePerson(db, db.people[0].id, -1);
    expect(db.people.map(p => p.name)).toEqual(['A']);
  });
});

describe('документы', () => {
  it('добавляет документ человеку', () => {

    expect(db.documents[0].pinned).toBe(false);
    expect(db.documents[0].pages).toHaveLength(1);

    expect(db.documents[0].pinned).toBe(false);

    db = addDocument(db, { personId: db.people[0].id, type: 'other', title: 'Х', pages: [page('a'), page('b')] });

    expect(res.db.documents).toHaveLength(0);
    expect(res.orphanFileIds).toEqual(['a', 'a_t', 'b', 'b_t']);
```

```js
import { emptyDb, addPerson, addDocument, togglePin } from '../model.js';
import { searchDocuments, sortDocuments, groupByType } from '../search.js';

function fixture() {

  const father = db.people[0].id;
  db = addPerson(db, { name: 'Дилноза', relation: 'мать' });
```

### Task 4: Хранилище — метаданные и файлы

**Files:**
- Create: `src/lib/db.js`, `src/lib/files.js`, `src/lib/image.js`
- Test: `src/lib/__tests__/db.test.js`

**Interfaces:**
- Consumes: `emptyDb()` из `model.js`
- Produces:
  - `loadDb() → Promise<Db>` — при отсутствии файла возвращает `emptyDb()`; при битом JSON читает `db.json.bak`; если и он битый — `emptyDb()` и `lastLoadError` = текст ошибки
  - `saveDb(db) → Promise<void>` — перед записью копирует текущий файл в `db.json.bak`
  - `lastLoadError() → string | null`
  - `saveBlob(blob, ext) → Promise<fileId>`
  - `readBlob(fileId) → Promise<Blob>`
  - `getDisplayUrl(fileId) → Promise<string>` — то, что можно положить в `<img src>`
  - `deleteBlob(fileId) → Promise<void>` — отсутствующий файл не считается ошибкой
  - `storageStats() → Promise<{ count, bytes }>`
  - `makeThumbnail(blob, maxWidth = 400) → Promise<Blob>`

  Внутри `db.js` и `files.js` — ветка `Capacitor.isNativePlatform()`: на телефоне Filesystem (`Directory.Data`, подпапка `vital/`), в браузере localStorage (метаданные) и IndexedDB (байты). Наружу — один и тот же интерфейс.

  - `setPin(pin)`, `hasPin() → Promise<boolean>`, `checkPin(pin) → Promise<boolean>`
  - `nextDelayMs(failCount) → number` — 0 для первых трёх попыток, затем 30000

- [ ] **Step 1: Тесты на чистую логику**

```js
  expect(nextDelayMs(2)).toBe(0);
});

  expect(nextDelayMs(3)).toBe(30000);
  expect(nextDelayMs(7)).toBe(30000);
});
```

- [ ] **Step 2: Экран блокировки**

Четыре точки, клавиатура 0–9 и «стереть». При первом запуске — установка PIN с подтверждением. Неверный PIN: точки дрожат, счётчик растёт, после третьего раза — обратный отсчёт.
